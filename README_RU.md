# ESP32 + RFM95 GNARL Прошивка

RileyLink-совместимая прошивка для **TTGO LoRa32 V1.6.1** (плата по умолчанию в этом форке)
с радиомодулем SX1276. Реализует протокол RFSpy/GNARL для связи с инсулиновыми помпами
Medtronic через iAPS/Loop/AndroidAPS. Поддерживаются также Heltec WiFi LoRa 32 V2 и ESP32-C6.

Ключевые возможности этого форка:
- **OTA-обновление по Wi-Fi** — двойное нажатие RST, без компьютера и кабеля
- **Автоматический откат** — если новая прошивка не подтвердилась за 60 секунд,
  загрузчик возвращает предыдущую
- **OLED-экран статуса** — батарея, частота, бар сигнала помпы, качество связи

## Готовая прошивка из GitHub Actions (без установки ESP-IDF)

В репозитории настроена сборка прошивки в облаке (`.github/workflows/firmware.yml`).
Каждая сборка публикует три артефакта:

| Артефакт | Содержимое | Назначение |
|----------|-----------|------------|
| `rileylink-ttgo` | `rileylink-ttgo.bin` | **Merged-образ** (bootloader + разметка + приложение) — только для прошивки по USB с адреса `0x0` |
| `rileylink-ttgo-ota` | `pickle-stable.bin` | **Образ приложения для OTA** — заливается через Wi-Fi-страницу в режиме OTA |
| `rileylink-ttgo-debug` | ELF + MAP | Для декодирования backtrace (addr2line) при крэшах |

⚠️ **Не перепутайте:** для OTA подходит только `pickle-stable.bin`. Merged-образ
в OTA-раздел не встанет.

### Разовая настройка

1. **Settings → Secrets and variables → Actions → New repository secret**:
   - `PUMP_ID` — серийный номер вашей помпы (например `123456`)
   - `PUMP_FREQUENCY` — частота (опционально, по умолчанию `868250000`)
2. Запустить сборку: **Actions → firmware → Run workflow** — готовые `.bin` появятся
   в артефактах сборки. Либо поставить тег для полноценного релиза:
   ```bash
   git tag v0.1 && git push origin v0.1
   ```
   Файл появится на странице **Releases**.

При запуске workflow можно переопределить без перенастройки секретов:
- `pump_id` — серийник помпы
- `pump_frequency` — частота в Гц
- `ble_name` — BLE-имя устройства (макс. 8 символов)

### Прошивка платы по USB (первичная / аварийная)

```bash
pip install esptool
esptool.py --port /dev/ttyUSB0 write_flash 0x0 rileylink-ttgo.bin
```

- Порт уточните: `ls /dev/ttyUSB* /dev/ttyACM*` (Linux), `ls /dev/cu.wchusbserial*` (macOS),
  `COMx` в Windows.
- Если прошивка не стартует — зажмите кнопку **BOOT** на плате при запуске esptool
  (на платах без кнопки BOOT контроллер обычно входит в загрузку сам).
- **Перед включением прикрутите антенну 868 МГц!**
- USB-прошивка нужна один раз. Дальше все обновления — по Wi-Fi (см. ниже).

## Обновление по Wi-Fi (OTA)

Во flash размечены два слота приложения (`ota_0` и `ota_1`) — новая прошивка пишется
в свободный слот, старая остаётся нетронутой как страховка.

### Как обновиться

1. **Войдите в режим OTA — двойное нажатие RST:**
   - нажмите RST **один** раз;
   - **дождитесь зажигания OLED** с текстом `GNARL2 <сборка> / 2x RST = OTA mode` (~1–2 с);
   - нажмите RST **второй** раз (не позже ~5 секунд после первого).

   ⚠️ Второе нажатие **не раньше, чем зажёгся экран**: счётчик живёт в приложении,
   и при нажатии быстрее ~0,5 с он не успевает записаться — тогда второй бут
   засчитывается как первый.
2. Подключитесь с телефона/ноутбука к Wi-Fi **`GNARL-OTA`**, пароль **`rileylink`**.
3. Откройте http://192.168.4.1, выберите файл **`pickle-stable.bin`**
   (артефакт `rileylink-ttgo-ota` из нужной сборки) → **Upload**.
4. Прогресс отображается на странице и на OLED (`[===   ] NN%`).
   По завершении плата перезагрузится сама.

### Первые 60 секунд — самопроверка

Новая прошивка стартует в режиме «проверяется». Если она проработала 60 секунд,
она подтверждает себя навсегда. **Если в первые 60 секунд нажать RST, выдернуть
питание или прошивка упадёт — загрузчик автоматически вернёт предыдущую версию.**

Это же — способ откатиться вручную: после OTA-обновления нажмите RST один раз
в первые 60 секунд.

### Если OTA-загрузка прервалась

Ничего страшного: повреждённый образ не пройдёт проверку, плата останется
на старой прошивке. Просто войдите в OTA-режим и повторите загрузку.

## Установка (сборка из исходников)

### 1. Установка ESP-IDF

```bash
# Клонировать ESP-IDF
git clone -b v5.4.1 --recursive https://github.com/espressif/esp-idf.git ~/esp/esp-idf

# Установить инструменты
cd ~/esp/esp-idf
./install.sh esp32

# Добавить в shell (добавить в ~/.bashrc или ~/.zshrc)
alias get_idf='. ~/esp/esp-idf/export.sh'
```

### 2. Настройка параметров помпы

В репозитории лежит `include/pump_config.h` со значением по умолчанию.
При сборке через GitHub Actions файл автоматически перезаписывается из
workflow input `pump_id` или секрета `PUMP_ID` — менять его руками не нужно.

Для локальной сборки отредактируйте `include/pump_config.h`:

```c
#ifndef PUMP_CONFIG_H
#define PUMP_CONFIG_H

#define PUMP_ID         "123456"      // Серийный номер помпы
#define PUMP_FREQUENCY  868250000     // Рабочая частота (Гц)

#endif
```

**Не коммитьте свой реальный серийный номер помпы в git** — для локальных сборок
это неизбежно, но в публичный репозиторий такие изменения пушить не стоит.

### 3. Сборка и прошивка

```bash
# Активировать окружение ESP-IDF
get_idf

# Перейти в проект
cd esp32rfm95

# Сборка
idf.py build

# Прошивка (замените порт на ваш)
idf.py -p /dev/cu.usbserial-0001 flash

# Мониторинг serial
idf.py -p /dev/cu.usbserial-0001 monitor

# Сборка + Прошивка + Мониторинг
idf.py -p /dev/cu.usbserial-0001 flash monitor
```

### 4. Чистая сборка

При изменении `sdkconfig.defaults`:

```bash
idf.py fullclean
idf.py build
```

## Конфигурация

### Опции (`include/module.h`)

```c
// Опции отладки (раскомментировать для включения)
// #define BLE_DEBUG      // Дамп BLE пакетов
// #define RADIO_DEBUG    // Дамп TX/RX пакетов

// Имя BLE устройства (макс. 8 символов)
#define BLE_NAME        "MYGN"

// Light sleep при отключённом BLE (~0.8mA vs ~20-40mA активного режима)
#define BLE_SLEEP
```

### Энергосбережение (`sdkconfig.defaults`)

- **Tickless idle** (`CONFIG_PM_ENABLE`) — CPU автоматически засыпает в idle
- **BLE_SLEEP** — light sleep ~0.8 мА при отключённом BLE (просыпается раз в 5 сек
  проверить подключение)
- **OLED-скринсейвер** — экран гаснет через 5 минут без BLE-подключения,
  просыпается при подключении или по кнопке
- Уровень логирования — INFO для приложения, ERROR для компонентов

## OLED-экран (TTGO)

На бортовой SSD1306 128×64 каждую секунду выводится статус:

```
MYGN    BLE:CONNECTED  <- имя (слева) + состояние (справа)
Batt 4.02V     87%    <- батарея
Freq 868.250 MHz      <- частота радио
Pump [====----] 5s    <- бар сигнала помпы (RSSI) + время последнего ответа
Pump ID 123456        <- серийник помпы из прошивки
Link 98% ok           <- доля успешных приёмов
Up 02:34:17           <- аптайм
```

RSSI за баром сглаживается скользящим средним (EMA, ~4 пакета).
Шкала бара: -95 dBm = пусто, -60 dBm и сильнее = полный — удобно
для подбора места размещения устройства.

**Сигнал о потере связи:** пока BLE не подключён, верхняя строка мигает
инверсией (~1 Гц) — разрыв видно с одного взгляда. Скринсейвер по-прежнему
гасит экран через 5 минут без подключения.

При загрузке первые ~1,5 секунды показывается экран-подсказка
`GNARL2 <сборка> / 2x RST = OTA mode` — по нему же видно, что плата дошла
до приложения (важно для входа в OTA-режим).

### Кнопка BOOT (GPIO0)

- **Короткое нажатие** — включить/выключить экран
- **Длинное нажатие (>1.5 сек)** — повернуть экран на 180°
  (ориентация сохраняется в NVS и переживает перезагрузку)

На части плат физической кнопки BOOT/PRG нет — тогда доступен только вход
в OTA-режим по двойному RST, на работу моста это не влияет.

## Использование с AAPS/iAPS/Loop

1. Прошить устройство
2. Открыть iAPS/Loop/AndroidAPS
3. Добавить новое устройство RileyLink, **выбрав его из списка найденных**
4. Устройство автоматически подключится и синхронизируется с помпой

⚠️ **Не используйте «Привязать RileyLink» (BLE-сопряжение/bonding)** — телефон
рвёт такое соединение, и приложение зависает на «Инициализация RileyLink».
Сопряжение не нужно: просто выберите устройство из списка.

⚠️ **После перезагрузки моста (кнопкой RST или OTA) приложение может не
переподключиться само.** Помогает: повторный скан в настройках RileyLink,
выключение/включение Bluetooth, в тяжёлом случае — перезапуск приложения.
Это поведение приложения, а не прошивки.

## Решение проблем

### Устройство не найдено в приложении
- Проверьте включён ли BLE на телефоне
- Перезагрузите устройство
- Проверьте serial монитор на ошибки

### Помпа не отвечает
- Проверьте, что при сборке workflow был указан правильный `pump_id`
  (input при запуске или secret `PUMP_ID`); на OLED-экране строка `Pump ID …`
  показывает серийник, зашитый в прошивку
- Проверьте частоту (обычно 868250000 Гц для EU)
- Убедитесь что помпа в зоне досягаемости (~1-2 метра)
- Смотрите строку `Pump [бар] Ns` на экране: бар — уровень сигнала,
  секунды — время последнего ответа помпы

### Двойной RST не открывает OTA-режим
- Нажимаете слишком быстро: второе нажатие — только **после зажигания экрана**
  (~1–2 с после первого), не раньше
- Проверьте в serial-логе строку `ota: reset count N (reason R)` — счётчик
  увеличивается только на перезагрузках кнопкой/питанием (reason 1)

### OTA-страница не открывается
- Убедитесь, что подключены именно к Wi-Fi `GNARL-OTA` (мобильный интернет
  может «перетягивать» трафик — отключите LTE на время)
- Адрес — http://192.168.4.1 (именно http, не https)

### Watchdog timeout
- Проверьте `CONFIG_ESP_TASK_WDT_TIMEOUT_S=30` в sdkconfig.defaults
- Выполните `idf.py fullclean && idf.py build`
